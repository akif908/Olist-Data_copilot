## 5. Observations for schema design

- `orders.order_status` values: ['approved', 'canceled', 'created', 'delivered', 'invoiced', 'processing', 'shipped', 'unavailable'].
- `orders.order_purchase_timestamp` range: 2016-09-04 21:15:19 to 2018-10-17 17:30:18.
- `customers.customer_id` is unique per row (99441 values) but `customer_unique_id` has 96096 distinct values across 99441 rows — customer_id identifies an order-side customer record, customer_unique_id identifies the actual customer.
- Timestamp columns are read as text by pandas; they map to PostgreSQL `timestamp`.
- ID columns are 32-char hex strings; they map to `varchar(32)` (or `text`).
- `order_items` price/freight and `payments.payment_value` are monetary → `numeric(10,2)`.
- Geolocation has no primary key and contains duplicate rows; it is a lookup, not an entity.
