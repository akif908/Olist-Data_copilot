# Phase 4 — Retrieval Evaluation

Generated by `python -m scripts.evaluate_retrieval`.

## Method

- Question set: `knowledge_base/eval/retrieval_questions.json` (16 manually verified, paraphrased Olist questions).
- Ground truth: hand-curated relevant knowledge chunks per question (metric / unsupported_metric / example / schema).
- Metrics: Recall@K, Hit@K for K in [1, 3, 5]; MRR over top-5.
- Each provider is ingested into its own eval collection over identical chunks; cosine similarity; no silent model switch.

## Notes

- Recall@K rewards retrieving ALL relevant chunks; Hit@K rewards finding at least one. MRR rewards ranking a relevant chunk first.
- The local baseline (`all-MiniLM-L6-v2`, 384-dim) is optional and requires `pip install -r requirements-baseline.txt`; it is used only for comparison, never as a silent fallback in production.
- Retrieval quality is necessary but not sufficient: Phase 5+ still validates and safely executes the generated SQL.
